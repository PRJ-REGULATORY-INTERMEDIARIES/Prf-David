# DATA DICTIONARY — G2 MAPPING BASE

**Version:** 1.0 (round 1, 2026-10-10) | **Encoding:** UTF-8, comma-separated, LF line endings, header row.
**Controlled vocabularies:** `mapping/schemas/mapping_vocabularies.json` (machine-readable; the lists below repeat them for reading).

The CSV files are build outputs. They are generated by `mapping/scripts/build_mapping_base.py` from the curation file of each round (`mapping/curation/round<n>.py`) and from the evidence logs. Do not edit them by hand: edit the curation file and rebuild.

**Conventions**

- `NOT_ASSESSED` means the information was not collected. It never means that the property is absent.
- An empty cell means "not applicable to this row".
- Multi-valued cells use `;` as separator.
- Every row of `resources.csv`, `resource_relations.csv` and `decisions_log.csv` produced so far is a provisional proposal by an AI agent. Confirmation by a researcher is recorded in separate columns.

## resources.csv

| Column | Content | Values |
|---|---|---|
| `resource_id` | Persistent opaque identifier. Never reused; carries no meaning | `MR-` + four digits |
| `seed_id` | Identifier in `inputs/seed_inventory_v0_1.csv`, when the row comes from it | `EU01`–`EU41` or empty |
| `registered_name` | Name exactly as in the seed inventory | Text or empty |
| `verified_name` | Name as given by the source | Text |
| `maintainer` | Organisation or persons responsible, as given by the source | Text or `NOT_ASSESSED` |
| `resource_category` | Proposed kind of resource | `DATASET`, `CORPUS`, `REPOSITORY`, `INFRASTRUCTURE`, `API`, `ACCESS_PORTAL`, `SEARCH_INTERFACE`, `CATALOGUE`, `DATA_DISTRIBUTION`, `BENCHMARK`, `ADMINISTRATIVE_REGISTER`, `DESCRIPTIVE_PAGE`, `STANDARD_OR_VOCABULARY`, `SOFTWARE_OR_PIPELINE`, `INDETERMINATE` |
| `category_status` | Whether the category was confirmed | `CANDIDATE`, `CONFIRMED` |
| `resource_set` | A = EU legislative and legal data; B = EU regulatory governance data | `A`, `B`, `AB` |
| `territorial_scope` | Geographic reach | `EU`, `EU_EEA_PLUS`, `NATIONAL_EU_CONNECTED`, `INTERNATIONAL`, `NOT_ASSESSED` |
| `eu_connection_note` | For national or international resources: the documented link to EU law or governance | Text or `NOT_ASSESSED` |
| `thematic_coverage` | What the resource contains, in the source's terms | Text or `NOT_ASSESSED` |
| `temporal_coverage` | Period covered, when stated | Text or `NOT_ASSESSED` |
| `observation_unit` | What one record represents | Text or `NOT_ASSESSED` |
| `update_mode` | Update frequency or discontinuation, when stated | Text or `NOT_ASSESSED` |
| `formats` | File or serialisation formats | List or `NOT_ASSESSED` |
| `access_modes` | How content is obtained | Tokens such as `WEB_SEARCH`, `BULK_DOWNLOAD`, `REST_API`, `API`, `SPARQL`, `RSS`; or `NOT_ASSESSED` |
| `identifiers_supported` | Legal or persistent identifiers present in the records | Text or `NOT_ASSESSED` |
| `historical_versions` | Versioning or snapshots, when stated | Text or `NOT_ASSESSED` |
| `access_conditions` | Registration, authentication, embargo or other conditions | Text or `NOT_ASSESSED` |
| `licence_or_reuse` | Licence code or reuse statement as given by the source; not a legal assessment | Text or `NOT_ASSESSED` |
| `description_url` | Page or record that describes the resource | URL or `NOT_ASSESSED` |
| `primary_access_url` | Main address where content is obtained | URL or `NOT_ASSESSED` |
| `individuation_status` | Whether the row counts as an independent resource | `INDIVIDUATED`, `CANDIDATE_SEPARATE` (probably separate, undecided), `CANDIDATE_NOT_INDEPENDENT` (probably a distribution, interface or part of another), `GROUP_PENDING_SPLIT` (placeholder for several entries not yet read) |
| `eligibility_preliminary` | Provisional scope judgement | `INCLUDE`, `UNCERTAIN`, `EXCLUDE` |
| `verification_status` | Amount of evidence | `DISCOVERED`, `PARTIALLY_VERIFIED`, `VERIFIED`, `INACCESSIBLE`, `OUT_OF_SCOPE`, `INDETERMINATE` (definitions in the mapping protocol, section 6) |
| `verification_date` | Date of the last verification | ISO date |
| `discovery_origin` | How the resource entered the base | `SEED`, `SYSTEMATIC_SEARCH`, `BACKWARD_FORWARD_DISCOVERY`, `EXPERT_SUGGESTION`, `OTHER` |
| `field_basis` | Source of each filled descriptive field, as `column:BASIS` | `PRIMARY_PAGE`, `API_METADATA`, `SEED_UNVERIFIED`, `AGENT_INFERENCE` |
| `classification_basis` | Who proposed the classification | `AGENT_PROVISIONAL`, `RESEARCHER_CONFIRMED` |
| `researcher_confirmed` | Whether a researcher confirmed the row | `NO`, `YES` |
| `evidence_ids` | Evidence consulted | Identifiers of `evidence_registry.csv` |
| `uncertainties` | What was not checked, what is doubtful | Text |

**Counting rule.** Counts of "individuated resources" use `individuation_status = INDIVIDUATED`. `GROUP_PENDING_SPLIT` rows are never counted as resources.

## access_endpoints.csv

| Column | Content | Values |
|---|---|---|
| `endpoint_id` | Resource identifier + `-E` + two digits | |
| `resource_id` | Resource the endpoint belongs to | |
| `endpoint_role` | What the address is | `DESCRIPTION_PAGE`, `ACCESS_PORTAL`, `SEARCH_INTERFACE`, `API`, `SPARQL_ENDPOINT`, `BULK_DOWNLOAD`, `CATALOGUE_ENTRY`, `REPOSITORY_RECORD`, `CODE_REPOSITORY`, `DOCUMENTATION`, `MIRROR_OR_REDISTRIBUTION`, `DATA_PAPER` |

| `access_status` | Result of the single test request | `ACCESSIBLE`, `JS_ONLY_SHELL` (answered, but the content needs JavaScript), `AUTH_REQUIRED` (HTTP 401), `BLOCKED_TO_TOOL` (HTTP 403 to the automated client), `NETWORK_ERROR`, `NOT_TESTED` |
| `http_status` | Status code of the last attempt | |
| `final_url` | Address after redirects | |
| `tested_at_utc` | Time of the test | ISO 8601 UTC |
| `evidence_id` | Capture or failure record | |
| `notes` | Remarks | |

`ACCESSIBLE` means that one unauthenticated GET returned content. It does not mean that the dataset behind the address was retrieved.

## resource_relations.csv

| Column | Content | Values |
|---|---|---|
| `relation_id` | `MREL-` + five digits | |
| `source_resource_id`, `target_resource_id` | Read as "source *relation* target" | |
| `relation_type` | Kind of relation | See below |
| `confidence` | Strength of the evidence | `HIGH`, `MEDIUM`, `LOW` |
| `relation_status` | `SUPPORTED`: stated by a primary source or by repository metadata. `CANDIDATE`: plausible, not established | |
| `basis` | Kind of evidence | `PRIMARY_PAGE`, `API_METADATA`, `AGENT_INFERENCE` |
| `evidence_ids` | Evidence | |
| `justification` | What the evidence says and what remains unchecked | |
| `assessed_by`, `researcher_confirmed`, `assessed_on` | Provenance of the judgement | |

| Relation | Meaning |
|---|---|
| `same_resource_as` | Two records describe one resource |
| `distribution_of` | The source is a package or channel giving access to all or part of the target |
| `derived_from` | The source was built from the target by selection, cleaning, annotation or transformation |
| `access_interface_for` | The source is an interface through which the target is consulted |
| `catalogues` | The source lists or describes the target |
| `part_of` | The source is a component of the target, kept by the same maintainer |
| `links_to` | The source's page links to or names the target; nothing more is claimed |
| `overlaps_with` | Distinct resources with partly coinciding content |
| `successor_of` | The source replaces the target |
| `uses` | The source employs the target (a standard, vocabulary or ontology) |

Rules enforced by the validator: an inferred relation has `LOW` confidence; a `SUPPORTED` relation cannot rest on inference or low confidence; every relation has evidence and a justification.

## discovery_log.csv

Three kinds of row, distinguished by `entry_type`.

| `entry_type` | Meaning | Filled columns |
|---|---|---|
| `SEARCH_RUN` | One registered query, executed once | `search_id`, `platform`, `query`, `language`, `executed_at_utc`, `total_reported`, `hits_returned`, `hits_linked_to_resources`, `evidence_id` |
| `RESOURCE_DISCOVERY` | How a resource entered the base: seed, search hit, or mention in a captured page | `resource_id`, `origin`; for hits also `search_id`, `platform`, `hit_rank`, `platform_record_id`, `hit_title`, `evidence_id` |
| `SEED_REFOUND_BY_SEARCH` | A seed (or a distribution or data paper of it) returned by a registered search | As above. A sensitivity indicator; it does not change the seed's origin |

`platform`: `DEU` data.europa.eu, `ZEN` Zenodo, `DVN` Harvard Dataverse, `DCT` DataCite, `OAX` OpenAlex, `HF` Hugging Face Hub, `GH` GitHub.
`total_reported` is the number of results the service says exist; only the first 25 were retrieved. Empty when the service reports none.
`hits_linked_to_resources = 0` marks a search that produced nothing recorded.

## evidence_registry.csv

| Column | Content |
|---|---|
| `evidence_id` | `EVS-nnn` stored search response; `EVC-nnnn` capture attempt of this phase; `EVH-nnnn` capture preserved from an earlier gate |
| `evidence_type` | `SEARCH_RESPONSE`, `PAGE_CAPTURE`, `ACCESS_FAILURE`, `HISTORICAL_CAPTURE` |
| `related_record` | Seed identifier or search identifier used as label when the request was made. For `EVC` rows it is a filing label, not the authoritative link to a resource |
| `url`, `final_url` | Requested address; address after redirects |
| `accessed_at_utc` | Time of the request |
| `outcome` | `CAPTURED`, `EXECUTED`, `FAILED` |
| `http_status`, `content_type`, `bytes` | As returned |
| `sha256` | Hash of the bytes received |
| `stored_file` | Path of the preserved file, relative to the project folder |
| `tool` | Script that made the request |
| `note` | For failures: number of attempts and last error |

A failed request is evidence of an access failure on that date. It is never evidence that the resource does not exist.

## decisions_log.csv

| Column | Content |
|---|---|
| `decision_id` | `DEC-` + four digits |
| `decision_type` | `IDENTITY`, `ACCESS`, `EVIDENCE_CONFLICT`, `INDIVIDUATION`, `NOT_INDIVIDUATED`, `SCREENING`, `SCOPE_OPEN`, `TAXONOMY`, `NEGATIVE_RESULT` |
| `subject` | Resources, searches or group of hits concerned |
| `decision`, `rationale` | What was done and why |
| `evidence_ids` | Evidence |
| `decided_by` | `AGENT_PROVISIONAL` or `RESEARCHER` |
| `decided_on`, `status` | Date; `OPEN_TO_REVISION` until a researcher confirms |

A change of classification is a new row. Earlier rows are not deleted.

## seed_audit.csv

A view with one row per original seed, joining the seed inventory with `resources.csv`, `access_endpoints.csv` and `resource_relations.csv`. `registered_name` and `registered_url` are copied from the inventory unchanged. `registered_url_role` says what the registered address turned out to be. `relations` lists outgoing relations as `type>target(status,confidence)` and incoming ones as `source>type(in;status,confidence)`.

## search_hits.csv

`search_id`, `rank`, `platform`, `platform_record_id`, `title`, `url`, `creator_or_publisher`, `year`, exactly as extracted from the stored responses. These are occurrences. Their number is not a number of resources.

## Rebuilding and checking

```
python mapping/scripts/build_mapping_base.py      # regenerate the tables
python mapping/scripts/validate_mapping.py        # consistency checks; exit code 1 on error
python -m unittest discover -s tests              # all tests, including the earlier 87
```
